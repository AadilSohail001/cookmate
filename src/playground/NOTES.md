# Notes

## Modal

My version handled opening, closing, Escape key, focus trapping, scroll locking, and focus return correctly.

Shadcn additionally:
- Used `@base-ui/react/dialog` instead of building from scratch, leveraging battle-tested focus trapping and portal logic.
- Implemented animated transitions (data-open/data-closed states with `animate-in`/`animate-out`).
- Provided a composable API (`Dialog`, `DialogTrigger`, `DialogContent`, `DialogTitle`, `DialogDescription`, `DialogClose`, `DialogFooter`).
- Used render prop pattern for the close button, allowing flexible positioning and styling.
- Added a backdrop/overlay with backdrop blur support and proper z-index isolation.

**Key improvements Shadcn made:**
1. **Library-backed ARIA** — `@base-ui/react` handles `role="dialog"`, `aria-modal`, `aria-labelledby`, and focus management automatically, reducing bugs.
2. **Portal + overlay composition** — Their overlay is a separate component (`DialogOverlay`) positioned between the portal and content, enabling click-outside-to-close and staggered animations.
3. **Animation states** — Used Tailwind's `data-open`/`data-closed` modifiers for enter/exit animations without JavaScript animation libraries.

---

## Tabs

My version switched panels on click and supported Arrow Left/Right, Home, and End keys.

Shadcn additionally:
- Used `@base-ui/react/tabs` which provides full keyboard navigation (Arrow keys, Home, End, Tab) and ARIA attributes out of the box.
- Used `class-variance-authority` (CVA) for variant-based styling (default vs line variant).
- Supported both horizontal and vertical orientations via `data-orientation` attribute.
- Used `data-active` state attribute for styling the active trigger instead of a JavaScript conditional.

**Key improvements Shadcn made:**
1. **Orientation support** — Handles both horizontal and vertical tab layouts with correct ARIA `aria-orientation`.
2. **Variant system** — CVA enables clean separation of base styles from variant overrides without conditional class strings.
3. **Data-state styling** — Uses CSS attribute selectors (`data-active`, `data-orientation`) instead of inline conditional classes, making the component more themeable.

## Disclosure

My version toggled visibility with `aria-expanded`, `aria-controls`, and a triangle indicator.

Shadcn does not include a dedicated Disclosure/Accordion component by default (it uses `@base-ui/react/accordion` via `npx shadcn add accordion`), but comparing to `@base-ui/react` patterns:

**Potential improvements:**
1. **Collapsible animation** — `@base-ui` uses `data-panel-open`/`data-panel-closed` states that allow CSS transitions for the open/close animation rather than just hiding/showing.
2. **Nested disclosure support** — A robust implementation handles nested disclosures correctly, managing which parent accordion sections remain open.
3. **Focus management on collapse** — When collapsing a disclosure, focus should move to the trigger button. My version handles this with the button remaining in the DOM.

## Summary

| Area | My Implementation | Shadcn/Base UI |
|------|------------------|----------------|
| Focus trap | Manual `querySelector` loop | Built into `@base-ui/react/dialog` |
| Portal | `createPortal` to `document.body` | `DialogPortal` component |
| Scroll lock | `document.body.style.overflow = "hidden"` | Built into dialog primitive |
| Keyboard nav | Manual event listeners | Built into each primitive |
| ARIA attributes | Manually set | Auto-generated by primitives |
| Styling variants | Inline conditionals | CVA + data-state selectors |
| Animation | None | CSS data-state transitions |
